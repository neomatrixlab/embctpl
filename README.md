# Embedded Project

## Overview

Embedded C starter template based on modern, target-based CMake.
It provides a minimal module layout, host test workflow, coverage, sanitizers, and ARM cross-compilation presets.

## Features

- Modern CMake with target-level compile/link settings
- Unit testing with preinstalled GoogleTest/GoogleMock
- Coverage report generation (`lcov` + `genhtml`)
- ASan/UBSan workflow for host debug
- Cross-compilation presets for ARM toolchains

## Prerequisites

- CMake >= 3.24
- Ninja
- GCC/G++ (host build)
- GoogleTest 1.14+ preinstalled (for unit tests), e.g. `/opt/googletest`
- Optional:
  - `lcov`, `genhtml` (coverage)
  - `clang-format`, `cppcheck`, `clang-tidy` (static checks)
  - ARM GNU toolchain (cross build)

## Quick Start

### 1) One-Time Project Setup

```bash
./scripts/setup-hooks.sh
```

This enables local git hooks (`pre-commit`, `commit-msg`) so local behavior matches CI.
The `pre-commit` hook enforces `check-format.sh`, `check-cppcheck.sh`, and `check-tidy.sh`.

If needed, create your own local `CMakeUserPresets.json` (gitignored) for machine-specific overrides such as `CROSS_TOOLCHAIN_ROOT`.

### 2) Template Initialization (must customize)

Before feature development, update these template-specific items:

- Project metadata in `CMakeLists.txt` (`project(...)` name/version/description)
- Toolchain path defaults in `cmake/toolchains/arm-linux-gnu.cmake` (`CROSS_TOOLCHAIN_ROOT`, `CROSS_TOOLCHAIN_PREFIX`)
- Product module layout under `src/` and matching public headers under `include/`
- Optional CI/tooling policy in `.gitlab-ci.yml`, `.clang-tidy`, and `scripts/`

### 3) First Build + Test (host)

```bash
cmake --preset host-debug --fresh
cmake --build --preset host-debug -j
ctest --preset host-debug
./build/host-debug/src/app
```

Expected results:
- Unit tests pass.
- App prints one CRC example line.

### 4) Optional Local Quality Checks

```bash
./scripts/check-format.sh
./scripts/check-cppcheck.sh
./scripts/check-tidy.sh
```

These commands are optional for manual runs because the git hooks already gate them on commit.
`check-tidy.sh` requires `build/host-debug/compile_commands.json`, generated by the host build above.

### 5) Coverage Workflow

```bash
cmake --preset coverage --fresh
cmake --build --preset coverage --target coverage
```

Coverage HTML report is generated at `build/coverage/coverage-html/`.
The coverage feature is controlled at top-level by `ENABLE_COVERAGE` (preset `coverage` sets it to `ON`).

### 6) Sanitizer Workflow

```bash
cmake --preset asan-ubsan --fresh
cmake --build --preset asan-ubsan -j
ctest --preset asan-ubsan
```

### 7) Cross-Compile Workflow (ARM)

```bash
cmake --preset cross-release --fresh
cmake --build --preset cross-release -j
```

### 8) Package Artifacts (CPack)

```bash
cmake --preset host-debug --fresh
cmake --build --preset host-debug -j
cpack --preset host-debug
```

Generated archives are written under `build/host-debug/` (e.g. `.tar.gz`, `.zip`).

## Troubleshooting

- `clang-tidy: compile_commands.json not found`: run `cmake --preset host-debug --fresh && cmake --build --preset host-debug -j`
- `ARM toolchain not found`: pass `-DCROSS_TOOLCHAIN_ROOT=/your/toolchain/path` or adjust `cmake/toolchains/arm-linux-gnu.cmake`
- `Could NOT find GTest`: install GoogleTest/GoogleMock first (example prefix: `/opt/googletest`), or pass `-DCMAKE_PREFIX_PATH=/opt/googletest`
- `coverage` target failed: install both `lcov` and `genhtml`
